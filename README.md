# ZeeTech website

Next.js 16 front end + Payload CMS 3 admin panel, in one app, on PostgreSQL.

- **Website** — `/`, campaign pages at `/<slug>`, case studies at `/work` and `/work/<slug>`,
  services at `/services` and `/services/<slug>`
- **Admin panel** — `/admin` (edit every section, images, testimonials, FAQs, leads, SEO, tracking)
- **Client feedback links** — `/feedback/<private-token>` (written or video feedback, reviewed before publishing)

The original static build is kept in `legacy/` for reference; the seed script imports its images.

## Performance levels

Each visitor's device gets a level that decides how much animation runs (`src/lib/perf.ts`):

| Level | What runs |
|---|---|
| **high** | everything as designed |
| **mid** | effects stay, but WebGL draws at lower resolution; half the petals, no petal blur |
| **low** | no WebGL / canvas effects (still pictures instead), collage stands still, no frosted glass |

A small script in `<head>` picks the starting level from the device (CPU cores, memory, Data Saver,
slow network). `PerfWatch` then measures the real frame rate and steps down if the page keeps
struggling; the level is remembered for a week. On phones the bars that stay on screen are
always solid rather than frosted.

To test a level, add `?perf=low`, `?perf=mid` or `?perf=high` to any address (kept in that
browser until `?perf=auto`).

## Run it locally

Needs Node 22.12+ (Node 24 recommended).

```bash
npm install
cp .env.example .env          # then set PAYLOAD_SECRET to a long random string
npm run dev                   # starts the local database + the site → http://localhost:3000 and /admin
npm run seed                  # once, in a second terminal — loads the current site content
```

`npm run dev` starts the built-in local Postgres (port 5433, no Docker needed) and stops it again
on Ctrl+C. If it says port 3000 is in use, an older dev server is still running — close that
terminal (or run `npx kill-port 3000`).

The first visit to `/admin` asks you to create the admin user (or set `SEED_ADMIN_EMAIL` /
`SEED_ADMIN_PASSWORD` when seeding). `node scripts/reset-dev-db.mjs` empties the local
database if you want to start over.

When you change a collection or block, run `npm run generate:types`, and before deploying
create a migration: `npm run migrate:create -- short-description`.

### Adding pages to a site that already has content
`npm run seed` only fills an empty site. Pages built later come with their own scripts; each one
only adds what is missing, so running it twice is harmless:

| Script (local / Vercel) | What it adds |
|---|---|
| `npm run work` / `npm run vercel:work` | The Our Work page and its six case studies; case studies without them get the inquiry form and client stories at the end |
| `npm run services` / `npm run vercel:services` | The six services, the Services page, and the menu / footer links to them |
| `npm run about` / `npm run vercel:about` | The About page, and “About Us” in the menu / footer pointing at it |
| `npm run contact-careers` / `npm run vercel:contact-careers` | The Contact and Careers pages; “Contact”, “Careers” and every “Start a project” button pointing at them |
| `npm run update-content` / `npm run vercel:update-content` | Small content fixes from design updates (e.g. the name under the photo in the project inquiry form) |
| `npm run cyber-blockchain` | Adds the Cybersecurity & blockchain service (page, Services list label, footer link). The Vercel build runs it once by itself |

On the VPS run them with `NODE_ENV=production` after `npm run migrate`.

## Using the admin panel

| Where | What the owner can do |
|---|---|
| **Pages → Home** | Edit, reorder, add or hide sections. Every text, image, button and list is editable. *Live preview* shows changes before publishing; *Publish changes* makes them live (the cache clears at once). |
| **Pages → Create new** | Build a campaign landing page from the same sections, e.g. slug `launch-offer` → `/launch-offer`. |
| **Services** | The six services: each one's page at `/services/<slug>` (hero, deliverables, process, questions) and its row on the Services page. Drag to reorder — the order sets the numbers (01, 02…) and which service the “Explore the next step” button leads to. |
| **Case studies** | The cards in “Selected work” and the `/work/…` pages: details (duration, client, status, chips), story text, full-width gallery pictures, and the sections at the end. Three other projects are shown as “Related projects” automatically. |
| **Testimonials** | Written or video feedback. Video can be an upload, YouTube, Vimeo or Bunny Stream link. |
| **FAQs** | Questions and answers (also sent to Google as FAQ structured data). |
| **Media** | All images and short videos. Set the *focal point* to control how an image is cropped. |
| **Inbox → Leads** | Every project inquiry, with the campaign it came from (UTM source / medium / campaign, ad click id, first page). Update the status as you follow up. |
| **Inbox → Feedback requests** | Collect client feedback (below). |
| **Site → Header / Footer** | Navigation, buttons, footer columns and contact strip. |
| **Site → Site settings** | Default SEO title / description / share image, organisation details, and tracking IDs (Google Tag Manager, GA4, Meta Pixel, LinkedIn, Search Console). |
| **Each page / case study → SEO tab** | Title, description and share image for Google and social media, with a search-result preview. |

### Collecting client feedback
1. **Inbox → Feedback requests → Create new** — client name, company, project.
2. Save, copy the **Private feedback link** and send it (or tick *Email the link to the client*).
3. The client writes a few lines, records a video on their phone, or pastes a video link, and
   ticks the permission box. Each link works once and expires after 30 days.
4. You get an email; the feedback appears in **Testimonials** as a **draft**. Tidy the quote,
   add a poster image, and press **Publish** — only then can it appear on the site.

**Videos:** client uploads up to 150 MB are stored on the server. For long or popular videos,
upload them to **Bunny Stream** (≈ $1–5 / month, adaptive streaming, no ads) or YouTube and paste
the link instead — streaming big files from the VPS slows the whole site. Players only load when
the visitor presses Play, so videos never slow the page down. Video testimonials are sent to
Google as `VideoObject` structured data; add a transcript to help search.

### Adding a language later
Everything is already set up for translation. Add the language to `localization.locales` in
`src/payload.config.ts` (e.g. `{ label: 'বাংলা', code: 'bn' }`), deploy, then switch the
*Locale* menu in the admin and translate. (Language-prefixed URLs and `hreflang` tags are the
remaining front-end step.)

## Deploy on the VPS (Ubuntu 24.04, 2 vCPU / 4 GB RAM or more)

```bash
# 1. server basics
sudo apt update && sudo apt install -y nginx git docker.io docker-compose-v2 certbot python3-certbot-nginx
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash - && sudo apt install -y nodejs
sudo npm install -g pm2

# 2. code
sudo mkdir -p /var/www && cd /var/www
git clone <repo-url> zeetech && cd zeetech

# 3. database (Postgres in Docker, only reachable from the server)
echo "POSTGRES_PASSWORD=$(openssl rand -hex 24)" > deploy/.env
(cd deploy && docker compose up -d)

# 4. app settings
cp .env.example .env
#   DATABASE_URL=postgresql://zeetech:<POSTGRES_PASSWORD>@127.0.0.1:5432/zeetech
#   PAYLOAD_SECRET=<openssl rand -hex 32>
#   NEXT_PUBLIC_SERVER_URL=https://example.com
#   SMTP_* and NOTIFY_EMAIL for lead / feedback emails

# 5. install, create tables, load content, build, start  (this order matters)
npm ci
NODE_ENV=production npm run migrate
NODE_ENV=production npm run seed
npm run build
pm2 start deploy/ecosystem.config.cjs && pm2 save && pm2 startup

# 6. web server + HTTPS
sudo cp deploy/nginx.conf /etc/nginx/sites-available/zeetech   # edit the domain first
sudo ln -s /etc/nginx/sites-available/zeetech /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d example.com -d www.example.com

# 7. nightly backups (database + media)
chmod +x deploy/*.sh
(crontab -l 2>/dev/null; echo "30 2 * * * /var/www/zeetech/deploy/backup.sh >> /var/log/zeetech-backup.log 2>&1") | crontab -
```

Then open `https://example.com/admin`, create the admin account, and fill in
**Site settings → Tracking** and **Organisation**.

**Updating the site later:** `git pull && ./deploy/deploy.sh`

**Notes**
- `media/` holds every uploaded file — it is backed up by `deploy/backup.sh`; set
  `RCLONE_REMOTE` there to also copy backups off the server.
- Nginx allows uploads up to 200 MB for client videos (`client_max_body_size`); keep it in step
  with `FEEDBACK_MAX_VIDEO_MB`.
- If tracking scripts are used for visitors in the EU/UK, add a cookie-consent banner.
